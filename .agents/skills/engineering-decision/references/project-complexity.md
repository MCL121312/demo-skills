# 项目复杂度评估

项目复杂度描述项目整体需要多少理解、协调、专业分析和控制。它不是当前问题
的 Cynefin 域，也不能单独决定行为模式。

## 评估维度

每个维度使用 `0-4` 评分：

| 分数 | 含义 |
| --- | --- |
| `0` | 几乎没有复杂性，已有稳定规则 |
| `1` | 简单，有成熟模式和少量依赖 |
| `2` | 存在一些分析、协调或约束 |
| `3` | 多因素相互影响，需要专家或跨团队协作 |
| `4` | 高度动态、不确定、相互依赖或错误代价极高 |

评估以下维度：

| 维度 | 关注内容 |
| --- | --- |
| `domain` | 业务规则、例外、领域知识和术语稳定性 |
| `technical` | 技术栈、算法、并发、数据一致性和方案成熟度 |
| `integration` | 服务、数据库、外部系统、接口和数据流依赖 |
| `organizational` | 团队规模、跨角色协调和流程复杂度 |
| `uncertainty` | 用户、目标、成功指标和因果关系的不确定性 |
| `change` | 需求、规则、依赖和监管的变化频率 |
| `operations` | 可用性、发布、回滚、监控、灾备和运维要求 |
| `risk` | 安全、隐私、合规、财务、数据和用户权益风险 |

## 评分锚点示例

锚点用于对齐打分口径，不是穷举。各维度 `0`、`2`、`4` 的典型画像，`1` 和 `3`
取相邻两档的中间态：

| 维度 | `0` | `2` | `4` |
| --- | --- | --- | --- |
| `domain` | 单一业务线，规则有文档 | 跨 2-3 个业务域，部分规则只在老员工脑中 | 平台级，多业务线规则深度耦合，无完整文档 |
| `technical` | 单体应用，主流框架 | 3-5 个微服务，有缓存或消息队列 | 大规模分布式，自研中间件，强 SLA |
| `integration` | 无外部依赖 | 内部 3-5 个系统加少量外部 API | 集成枢纽，对接数十个含遗留系统，数据格式不统一 |
| `organizational` | 1-2 人自决 | 跨 2-3 个团队，有明确接口人 | 跨公司或事业部，多方利益冲突，协调成本高 |
| `uncertainty` | 需求与验收标准明确 | 主方向明确，需 1-2 轮验证 | 待解决什么问题本身待探索，需从访谈开始 |
| `change` | 半年不改核心逻辑 | 按周迭代，常有临时需求插入 | 探索期方向随时调整，边做边改 |
| `operations` | 单机部署，挂了重启即可 | 多环境、CI/CD、常规监控告警 | 多集群或多活，灰度发布，严格变更管控 |
| `risk` | 内部工具，无资金或用户影响 | 部分用户体验受损，可快速回滚 | 资金、数据或合规风险，可能承担法律责任 |

打分必须在 `evidence` 里写一句理由，例如 `technical: 3 —— 自研分布式事务
框架，无成熟社区方案`。

评分看证据不看规模：10 人团队可以做出 `risk: 4` 的金融核心；百人团队也可能
只有整体 `medium-low` 的内部系统。

## 评估原则

- 必须记录证据和置信度，不能只给分数。
- 维度不明时使用 `unknown`，不要用 `0` 代替缺失信息。
- 任一关键维度（`organizational`、`uncertainty` 或 `risk`）为 `unknown` 时，不计算
  总体平均分，`overall` 保持 `unknown` 或 `provisional`。
- 识别 `dominant_sources`，说明复杂度主要来自哪里。
- 不要用代码量、文件数量或团队人数单独推断复杂度。
- 项目整体复杂度高，不代表当前变更一定复杂。
- 项目规模小，也不代表用户问题或因果关系简单。

## 总体等级

如果所有维度都有可信分数，默认使用八个维度的等权平均作为参考，不使用未声明的
隐藏权重：

| 平均分 | 等级 |
| --- | --- |
| `0.0-0.9` | `low` |
| `1.0-1.9` | `medium-low` |
| `2.0-2.9` | `medium` |
| `3.0-3.4` | `high` |
| `3.5-4.0` | `very-high` |

平均分只用于统一讨论和触发进一步调查，不能替代判断。若 `risk` 或 `uncertainty`
达到 `3` 或 `4`，必须提高参与度和确认门槛。若总体等级被人工判断覆盖，必须记录
覆盖原因。

## 必须分开记录的结果

```yaml
assessment:
  project_complexity: high
  current_problem_domain: complicated
  uncertainty: medium
  risk: high
  behavior_mode: expert-analysis
```

含义分别是：项目整体复杂度、当前问题的 Cynefin 域、当前不确定性、风险水平和
推荐行为。不要把它们合并成一个“项目属于某域”的结论。
