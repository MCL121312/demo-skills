# Cynefin 域定义

分类当前问题的工作状态，不要给产品或组织永久贴标签。信息不足时使用
`confused`，不要猜测成其他域。

## `clear`：清晰域

目标、规则、输入和验收条件明确，因果关系稳定且可重复验证。使用
`Sense -> Categorize -> Respond`，低风险且可逆时可以直接推进。

## `complicated`：繁杂域

问题存在可知答案，但需要专家知识、方案比较或技术评估。使用
`Sense -> Analyze -> Respond`，先说明评价标准，再比较候选方案和权衡。

## `complex`：复杂域

结果依赖用户行为、采用率、市场反馈或组织协作，需求和因果关系尚未验证。
使用 `Probe -> Sense -> Respond`，把猜测写成假设，优先实验、原型、访谈或
MVP 切片，不要把未经验证的详细设计写成稳定承诺。

## `chaotic`：混乱域

存在事故、主动伤害、数据丢失、安全事件或快速扩大的故障，立即降低损害比
理解完整因果关系更重要。使用 `Act -> Sense -> Respond`，先止损和恢复，稳定
后再重新分类。

## `confused`：未明状态

信息不足以区分其他域，或利益相关者目标冲突且没有授权决策者。先整理已知/未知、
冲突点和高影响问题，不要急于生成正式详细设计。

## 注意事项

- 可使用一个主域和一个备选域，不要伪造高置信度。
- `chaotic` 表示需要立即稳定的状态，不等同于“需求复杂”。
- `complex` 不等于“技术难”；技术难但答案可知通常属于 `complicated`。
- 新证据可以触发迁移，例如 `confused -> complex -> complicated -> clear`。
