# 用户参与度策略

| 等级 | Agent 行为 |
| --- | --- |
| `L0` | 自动推进并报告结果 |
| `L1` | 自动推进，公开关键假设并邀请纠正 |
| `L2` | 提供少量方案，让用户或决策者选择 |
| `L3` | 以假设、问题、证据和决策组成短循环 |
| `L4` | 用户主导决策，Agent 负责整理和起草 |

## 默认映射

| 情况 | 默认等级 |
| --- | --- |
| `clear` 且低风险、可逆 | `L0-L1` |
| `complicated` 且存在重要方案权衡 | `L1-L2` |
| `complex` 或结果依赖用户行为 | `L2-L3` |
| `chaotic` 或正在造成伤害 | `L3-L4` |
| `confused` 或存在明显冲突 | `L3-L4` |

## 提高参与度

出现以下任一条件时，提高至少一个等级，必要时要求确认：

- 决策不可逆或回滚成本很高。
- 涉及安全、隐私、合规、资金、数据完整性或用户权益。
- 改变范围、负责人、外部契约或用户承诺。
- 影响多个团队、系统或用户群。
- 证据薄弱、利益相关者冲突或需求来源不明。

用户要求“全自动”不能覆盖高影响确认门槛。只有在低风险、可逆且范围明确时，
才可以降低参与度。

## 提问规则

- `L0-L1`：尽量先做，再报告，不为低影响缺口阻塞。
- `L2`：只问会改变方案选择的问题。
- `L3-L4`：先确认目标、边界、决策权和关键假设，再继续。
- 单轮默认最多三个高影响问题，除非用户明确要求访谈模式。
