# 信息分层

所有 Skill 共用的信息分类体系。记录内容时严格区分各层，不把推断写成事实。
本文件的证据规则是不可覆盖的硬底线，见 `conventions.md`。

## 分层定义

| 层 | 含义 | 示例 |
| --- | --- | --- |
| `facts` | 已提供或验证的信息 | 当前订单服务使用 MySQL |
| `goals` | 希望达成的结果 | 查询失败率低于 0.5% |
| `constraints` | 不能随意改变的条件 | 不能更换数据库 |
| `assumptions` | 暂时采用但未验证的判断 | 用户更需要精确搜索 |
| `unknowns` | 当前不知道的信息 | 主要用户是谁 |
| `conflicts` | 目标、事实或立场之间的互斥断言 | 产品要快，安全团队要求完整审计 |
| `risks` | 可能的负面结果和处理方式 | 迁移可能导致数据不一致 |
| `decisions` | 已由授权者确认的选择 | 第一阶段只支持精确搜索 |

## 证据规则

- 可在条目中内联注明来源和置信度，例如：
  `"当前订单服务使用 MySQL（来源：架构文档，置信度：高）"`。
- 不要把推断或候选方案写入 `facts`，应放入 `assumptions` 或 `unknowns`。
- 建议和候选方案不能写入 `decisions`，除非有授权者和确认状态。
- 代码中的现有行为可以作为事实，但不能自动变成期望行为。
- **推论不得写成事实**：这是所有 Skill 的共同底线。

## 在实施链中的落法

现场报告默认是待验证的声称。信息分层在实施场景中的体现：

- 实施人员亲见 → `facts`（证据等级：亲见）
- 客户口述但无人验证 → `assumptions`（证据等级：客户口述）
- 整理者推测 → `assumptions`（证据等级：推测）
- 没人提过的信息 → `unknowns`

证据等级不是标签，是门槛：等级为"推测"的条目不得标已确认；
缺陷类"未复现"时既不能标已确认也不能交接。
