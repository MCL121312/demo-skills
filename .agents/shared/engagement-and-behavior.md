# 用户参与度与行为模式

所有 Skill 共用的行为约束体系。本文件的数值是基线，覆盖规则见 `conventions.md`。

## 参与度等级（L0-L4）

| 等级 | Agent 行为 |
| --- | --- |
| `L0` | 自动推进并报告结果 |
| `L1` | 自动推进，公开关键假设并邀请纠正 |
| `L2` | 提供少量方案，让用户选择 |
| `L3` | 以假设、问题、证据和决策组成短循环 |
| `L4` | 用户主导决策，Agent 负责整理和起草 |

### 默认映射

| 情况 | 默认等级 |
| --- | --- |
| `clear` 且低风险、可逆 | `L0-L1` |
| `complicated` 且存在重要方案权衡 | `L1-L2` |
| `complex` 或结果依赖用户行为 | `L2-L3` |
| `chaotic` 或正在造成伤害 | `L3-L4` |
| `confused` 或存在明显冲突 | `L3-L4` |

### 提高参与度的条件

出现以下任一条件时，提高至少一个等级：

- 决策不可逆或回滚成本很高。
- 涉及安全、隐私、合规、资金、数据完整性或用户权益。
- 改变范围、负责人、外部契约或用户承诺。
- 影响多个团队、系统或用户群。
- 证据薄弱、意见相互冲突或需求来源不明。

用户要求"全自动"不能覆盖高影响确认门槛。

## 行为模式

### `direct-execution`

目标、规则和验收条件清晰，方案成熟，风险低且操作可逆。
允许：直接推进、实现、测试。阻止：不可逆操作、范围变化。

### `expert-analysis`

答案可知，但存在技术方案、成本、性能、安全或维护性权衡。
允许：比较方案、建立评价标准、分析权衡。需要确认：关键架构选择。

### `iterative-discovery`

用户问题、采用结果、目标或因果关系尚未验证。
允许：提出假设、设计实验、原型和 MVP。阻止：把未验证设计写成正式承诺。

### `stabilization`

事故、数据丢失、安全事件或主动伤害正在发生。
允许：止损、隔离、恢复。阻止：普通需求访谈或长期架构承诺。

### `clarification`

信息不足、目标冲突或边界不清。
允许：整理已知/未知、冲突和高影响问题。阻止：生成伪正式设计。

### `review-and-alignment`

已有多个文档、团队意见或候选方案，需要检查一致性。
允许：找矛盾、做追踪、提出决策问题。阻止：静默选择有争议的方案。

### 模式与参与度配对

| 行为模式 | 默认参与度 | 说明 |
| --- | --- | --- |
| `direct-execution` | `L0-L1` | 低风险可逆，执行后报告 |
| `expert-analysis` | `L1-L2` | 给出方案与权衡，让用户选择 |
| `iterative-discovery` | `L2-L3` | 短循环验证，边做边确认 |
| `stabilization` | `L3-L4` | 止损动作需即时确认 |
| `clarification` | `L3-L4` | 以问题补齐信息，用户主导 |
| `review-and-alignment` | `L2-L3` | 找矛盾并提交决策问题 |

配对是默认起点，不锁定组合：模式决定做什么，等级决定用户参与多少；
提高参与度的条件满足时仍须提高等级。

## 提问规则

- `L0-L1`：尽量先做，再报告，不为低影响缺口阻塞。
- `L2`：只问会改变方案选择的问题。
- `L3-L4`：先确认目标、边界和关键假设，再继续。

数量基线：**单轮最多三个高影响问题**。用户明确要求访谈模式时不设上限。

各 Skill 可按阶段覆盖这个基线，覆盖必须显式声明阶段、数值和单位；数量是兜底
上界而不是目标值，筛选与凑数规则见 `conventions.md`。
