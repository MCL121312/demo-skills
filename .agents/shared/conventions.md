# 共享约定

`shared/` 下所有文档给出的是**基线默认值**，不是各 Skill 的最终值。本文件定义
基线与覆盖的关系，避免同一条规则在多个 Skill 里出现互相矛盾的默认值。

## 基线与覆盖

| 概念 | 含义 |
| --- | --- |
| 基线 | `shared/` 文档中给出的默认值，未被覆盖时直接生效 |
| 覆盖 | 某个 Skill 为特定阶段声明的不同值 |

覆盖规则：

1. Skill 可以为特定阶段覆盖基线值，但**必须在该 Skill 内显式写明作用域**：
   适用阶段、数值和单位三项齐全，缺一项视为未覆盖。
2. 覆盖需要附一句依据，说明为什么这个阶段与基线不同。
3. 同一 Skill 内出现多个覆盖值时，集中在一张表里声明，不散落在正文各处。
4. 未显式覆盖的项按基线执行，不得靠推断自行调整。

冲突判定顺序：

```text
Skill 内带作用域的覆盖  >  shared 基线  >  无作用域的裸数值（视为笔误，按基线执行）
```

## 用词

框架自己造的词（Cynefin 域、行为模式、参与度、决策简报、文档契约、约束文件……）必须满足三条，否则不得使用：

1. **一处定义。** 所有自造词登记在 `glossary.md`，一行一词：词、含义、用在哪、能否出现在用户可见输出。不登记的词不得在 SKILL.md 与 references/ 里使用。
2. **一名一概念，一概念一名。** 同名不同义必须改名，触发即改，不留给下一版；同一概念禁止同义轮换。
3. **优先沿用既有词。** 能用 OOAD / UML / Cynefin / SRS / ISO 29148 / 行业标准里已有的词，就不造新词；造词必须能在不查文档的情况下用一句大白话解释清楚。

用户可见输出里只出现业务语言：框架术语一律不出现在面向实施人员、客户或评审者的文字里（见 `engagement-and-behavior.md`）。自造词只允许出现在 SKILL.md、`references/`、`glossary.md` 三处。

## Skill 描述

`SKILL.md` frontmatter 的 `description` 只用于**路由**：决定这个 Skill 该不该被加载。

- 只写三件事：做什么、什么时候用、什么时候不用。必须出现「用于」与「不用于」。
- 上限 240 字。触发场景列举高信号词，不追求穷举；中英文触发词各留最常用的几个。
- **行为规则不写进描述**：流程、门槛、判断顺序、输出禁忌都写在正文。描述里出现行为规则会被重复实现，且挤占路由判断。
- 触发词可以收用户的多种口语说法（如「问题单」），但产出物的名字只能有一个（见 `glossary.md`）。

## 不可覆盖的硬底线

以下约束不接受任何 Skill 覆盖，也不接受用户要求"全自动"或"别问那么多"来绕过：

- 推论、猜测和建议不得写成事实或已确认决策（见 `information-layers.md`）。
- 高影响、不可逆、涉及资金、数据完整性、安全合规的操作必须保留确认门槛
  （见 `engagement-and-behavior.md`）。
- 提高参与度的条件一旦满足，必须提高，不得因阶段或效率考虑跳过。
- 存在正在扩大的伤害时优先止损，不得先做常规需求分析（见 `cynefin.md`）。
- 多方意见冲突时，分别记录各方立场与理由，不静默选边。
